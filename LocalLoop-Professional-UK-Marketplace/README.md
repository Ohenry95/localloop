# LocalLoop — marketplace foundation

A UK-focused Groupon-style local deals marketplace codebase. It is beyond the previous demo: persistent SQLAlchemy models, customer accounts, business application/review, deal moderation, Stripe Connect Express onboarding, Stripe Checkout destination charges with a 15% application fee, signed Stripe webhook handling, vouchers only after verified payment, and PostgreSQL deployment configuration.

**Important:** this is an implementation foundation, not a claim that a live marketplace is launch-ready. Do not accept real customers or payments until the deployment, security, operational, tax/accounting, consumer-law, refund/cancellation, privacy, email verification, abuse/rate limiting, inventory race handling and end-to-end Stripe tests are complete. Legal pages are drafts. The code does not implement a refund/admin voucher-redeem workflow or customer support tools yet.

## Beginner path

1. Extract this ZIP on your computer.
2. Open the folder in a code editor (VS Code is suitable) or upload its contents into a new GitHub repository.
3. Deploy with Render using `render.yaml` as a Blueprint, or create a Python web service linked to the repo.
4. Add environment variables in Render's dashboard. Never put actual secrets into GitHub.
5. Start in Stripe **test mode** and test with Stripe test cards only.
6. Complete the launch checklist below before switching to live mode.

## Environment variables

- `LOCALLOOP_ENV=production`
- `LOCALLOOP_SECRET_KEY`: generated by Render; keep private.
- `DATABASE_URL`: PostgreSQL connection string. Render blueprint provisions a managed PostgreSQL database.
- `STRIPE_SECRET_KEY`: test key initially (`sk_test_...`). Later use a live key only after Stripe has approved the business/account setup.
- `STRIPE_WEBHOOK_SECRET`: signing secret from the Stripe webhook endpoint.
- `ADMIN_EMAIL`: the email address that should receive the admin role on its first account registration. Set this before creating the account; protect that mailbox and remove/change this bootstrap approach before public launch.

## Stripe Connect configuration

1. Create/configure the LocalLoop platform in Stripe and enable Connect.
2. Keep Stripe in test mode while building.
3. Add the deployed URL as a webhook endpoint: `https://YOUR-DOMAIN/stripe/webhook`.
4. Subscribe to `checkout.session.completed` and `checkout.session.expired` at minimum. Copy the endpoint signing secret into `STRIPE_WEBHOOK_SECRET`.
5. Verify Express onboarding, charge and transfer capabilities, application fee, seller payout timing, refund/dispute behavior and webhook retries in test mode.
6. The app uses destination charges with `application_fee_amount` equal to 15% of the offer price. Stripe processing fees, refunds, disputes and platform liability need a documented agreement and careful review.

## Local run

Python 3.11+ recommended:

```bash
python -m venv .venv
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# Set LOCALLOOP_SECRET_KEY, ADMIN_EMAIL, STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET in your shell/.env loader.
python app.py
```

With no Stripe key, the website runs but checkout and Connect onboarding remain disabled. Never use actual payment keys in a local sample environment.

## Before public launch

- Use a managed PostgreSQL database with backups, restore test and monitoring.
- Add verified email/password reset, rate limiting via shared storage, bot/abuse controls, audit trails and security review.
- Add robust stock reservations/expiry recovery, refunds/cancellations, voucher redemption, support/admin workflows and idempotent webhook reconciliation.
- Test concurrent purchases and every webhook/retry/failure path.
- Complete UK marketplace, consumer protection, privacy, cookie, VAT/tax, accessibility and seller contract reviews with qualified professionals.
- Confirm the operator is eligible to run the Stripe account. Under-18 founders must not misstate age or account ownership; obtain Stripe confirmation and any required adult/guardian involvement.
- Never commit `.env`, API keys, webhook secrets, database credentials or customer exports.
